# Beyond Accuracy/Brier/LogLoss: Calibration Diagnostics and RPS

## Summary

Added four new metrics to `src/validation/metrics.py`, wired automatically
into `BacktestEngine` for every future backtest: **Expected Calibration
Error (ECE)**, the **Brier score decomposition** (reliability/resolution/
uncertainty), a **binned calibration table**, and the **Ranked Probability
Score (RPS)** for models with native tie/OT prediction. These aren't
cosmetic additions — applied to data already collected this session, they
immediately produced two findings that the standard three metrics had been
obscuring.

## Why these four

Accuracy/Brier/LogLoss each collapse a model's full prediction behavior
into one number. That's useful for a single "did it win" verdict, but this
project has repeatedly cared about *why* one model beats another —
KRACH's overconfidence, HockeyLRMC's under-confidence, whether a model's
edge comes from being sharper or better-calibrated. The four additions
below each answer one of those "why" questions directly, using data
already being generated by every backtest — no new model fits required.

## 1. Brier score decomposition (Murphy 1973)

```
Brier = Reliability - Resolution + Uncertainty
```

- **Uncertainty** — the test set's own base-rate variance. Identical for
  any two models evaluated on the same games; doesn't distinguish models.
- **Reliability** (lower is better) — calibration error in Brier's own
  units: average, per probability bin, of (predicted − actual)².
- **Resolution** (higher is better) — how much the model's predictions
  actually discriminate winners from losers, independent of whether
  they're calibrated: average, per bin, of (bin's actual rate − overall
  base rate)².

**Result on the 5-year/20-split backtest** (`python -m
tests.calibration_metrics_backtest`):

| Model | Brier | Reliability | Resolution |
|---|---|---|---|
| **ELO** | 0.1739 | **0.0039** | 0.0204 |
| Massey | **0.1721** | 0.0055 | **0.0239** |
| RPI | 0.1750 | 0.0068 | 0.0219 |
| HockeyBT | 0.1753 | 0.0078 | 0.0225 |
| KRACH | 0.1840 | 0.0159 | 0.0228 |

**ELO has the best reliability (calibration) of any model in the roster —
better than Massey.** Massey's better overall Brier score comes from
having the best *resolution* instead. Every prior report in this project
said "Massey wins," which is true for the bottom line, but obscures that
ELO is doing something genuinely different (and, on this one specific
axis, better).

## 2. Expected Calibration Error (ECE)

The game-count-weighted average `|predicted − actual|` across probability
bins — isolates calibration the same way reliability does, but in
directly-interpretable probability units rather than squared-error units.

| Model | ECE |
|---|---|
| **ELO** | **0.0162** |
| Massey | 0.0278 |
| RPI | 0.0455 |
| HockeyBT | 0.0430 |
| KRACH | **0.0891** |

KRACH's ECE is more than 5x ELO's and more than 3x Massey's — the
calibration gap this project has discussed since the very first NPI/KRACH
critique is now a single interpretable number.

## 3. The calibration table makes the gap concrete, not abstract

`get_calibration_table()` bins predictions and reports predicted vs. actual
outcome rate per bin. For Massey and KRACH (pooled, n=8,371):

| Predicted bin | Massey says | Massey actual | KRACH says | KRACH actual |
|---|---|---|---|---|
| 90–100% | 92.8% | 93.0% | **94.2%** | **82.2%** |
| 0–10% | 7.5% | 13.0% | **5.9%** | **28.3%** |

This is the same "1284x rating spread → overconfidence" finding from
`reports/hockey_bt_results.md`, but no longer abstract: when KRACH calls a
team a 94% favorite, it's wrong nearly one time in five. Massey's most
confident bin is almost exactly right. Full tables for both models are in
`data/validation/backtest_results/` via `get_calibration_table()`.

## 4. Ranked Probability Score (RPS) — evaluating a capability never checked before

HockeyBT and DixonColes predict genuine 3-outcome distributions (home
win/tie/away win) via `predict_outcomes()`, but every backtest before this
collapsed that to a single `P(home win) + 0.5·P(tie)` scalar for
comparability with two-outcome models. That's the right choice for
comparing across the whole roster, but it means **the tie predictions
themselves were never evaluated** — a real capability built and never
checked.

RPS is the correct generalization of Brier to an *ordered* categorical
outcome (away-win < tie < home-win is a genuine ordinal scale — a model
predicting a tie when a home win occurred should be scored better than one
predicting an away win, and RPS respects that; a naive multiclass score
wouldn't). `BacktestEngine` now computes it automatically whenever a model
exposes `predict_outcomes()`, alongside (not instead of) the standard
metrics.

**First result:** HockeyBT's tie predictions, 20-split backtest: mean RPS
0.224, mean predicted P(tie) 7.25% vs. actual tie rate 8.28% (mildly
conservative, reasonably calibrated on ties specifically). No prior report
in this project checked this.

## Implementation notes

- All four functions live in `src/validation/metrics.py`, matching the
  existing `calculate_accuracy`/`calculate_brier`/`calculate_log_loss`
  conventions (operate on a `HomeWinProb` + target-column DataFrame; RPS
  additionally needs `P_Home`/`P_Tie`/`P_Away` columns).
- `BacktestEngine.run()` computes ECE and the Brier decomposition for
  *every* model automatically (no config needed) and RPS whenever
  `hasattr(model, 'predict_outcomes')` — checked once per model per split,
  present as `NaN` (not `0.0`) for models that don't support it, so it's
  never silently compared against models it doesn't apply to.
- `save_results()`'s aggregate CSV now includes all of these; existing
  callers that only read `Accuracy`/`Brier`/`LogLoss` are unaffected (new
  columns are additive).
- Tests: [tests/unit/test_metrics.py](../tests/unit/test_metrics.py) (10
  tests) — including a direct check that the decomposition's three terms
  actually reconstruct the plain Brier score (the defining property of a
  decomposition, not just "produces some numbers"), and that RPS
  correctly penalizes ordinal distance (tie-guess-on-a-win scores better
  than away-guess-on-a-win).
- Reproducible:
  [tests/calibration_metrics_backtest.py](../tests/calibration_metrics_backtest.py)
  (`python -m analysis.exploratory.calibration_metrics_backtest`).

## What this changes about how to read past reports

- `reports/massey_calibration_results.md` and `reports/hockey_bt_results.md`
  described KRACH's problem as "high rating spread → overconfidence" in
  the abstract; the calibration table above is the concrete version of the
  same claim.
- **ELO's genuine strength (best calibration) was not visible in any prior
  report** — every past comparison used aggregate Brier/LogLoss, where
  Massey's superior resolution dominates the headline number. Worth
  keeping in mind if a use case ever specifically needs well-calibrated
  probabilities more than sharp ones (e.g. a betting-market-style
  application) rather than the tournament-selection use case this project
  has centered on, where discriminating power (resolution) matters more.

## Open items

1. **Calibration table / ECE weren't computed for every model in the
   roster** (only the two extremes, Massey and KRACH, for the illustrative
   table) — the underlying function works for any model, this is just a
   reporting choice to keep this document focused.
2. **RPS was only checked for HockeyBT**, not DixonColes — DixonColes also
   exposes `predict_outcomes()` and would work identically with the same
   `BacktestEngine` wiring; not run here for scope reasons.
3. **No rank-stability or bubble-team-accuracy metric was formalized** —
   these were part of the original answer to "what other metrics matter"
   but are more involved (require refitting across cutoffs, or defining
   a "bubble" cutoff) and were left as concepts rather than shipped code.
